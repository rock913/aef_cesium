#### 1. 真实雷达卫星源数据谱系 (Sentinel-1 SAR Data Lineage)
- **卫星星座**：欧空局（ESA）Copernicus 计划 Sentinel-1A / Sentinel-1B 双星微波雷达系统；
- **波段与波长**：C 波段（中心频率 5.405 GHz，波长 $\lambda = 5.55\text{ cm}$）；
- **成像模式**：干涉宽幅模式（Interferometric Wide Swath, IW），采用地形观测渐进扫描（TOPSAR）技术；
- **极化与分辨率**：同向极化 VV 单视复数（SLC）产品，地面像元分辨率约 $5\text{ m} \times 20\text{ m}$；
- **轨道轨道覆盖**：
  - 升轨轨道（Ascending）：Track 040，卫星向北偏西飞行，天线向右侧（东向）侧视观测；
  - 降轨轨道（Descending）：Track 069，卫星向南偏西飞行，天线向右侧（西向）侧视观测；
  - 入射角 $\theta \approx 39.2^\circ$（近轨）$\sim 43.8^\circ$（远轨）。

#### 2. 地形拓扑与大气延迟辅助数据集 (Topography & Tropospheric Reference)
- **地形参考相位消除**：采用欧洲航天局 Copernicus DEM GLO-30（30 米空间分辨率，全球绝对高程精度 $< 4\text{ m}$），用于模拟并剔除干涉相位中的地形固有高程贡献 $\phi_{\text{topo}}$；
- **对流层湿延迟校正**：欧洲中期天气预报中心 ECMWF ERA5 逐小时气象再分析格点数据（水平分辨率 $0.25^\circ \times 0.25^\circ$，垂直 37 个气压层），通过积分气压、气温和比湿计算天顶对流层湿延迟（ZWD），消除华南雨热同期强烈的对流层水汽相位湍流屏障；
- **精密轨道校正**：引入欧空局重访 21 天后发布的精轨星历（POEORB），将卫星天线空间基线误差控制在 5 cm 以内。

#### 3. 核心干涉反演算法工业规范 (Processing Chain & Algorithms)
- **核心算法引擎**：Miami MintPy（Small Baseline Subset, SBAS 小基线集时序反演框架）与 NASA ISCE2（干涉雷达前置处理）；
- **干涉图网络构建**：设置时空双基线门限，空间垂直基线 $B_\perp < 150\text{ m}$，时间基线 $\Delta t < 60\text{ days}$，构建冗余闭合的干涉三角形网络；
- **去相干降噪**：距离向与方位向采用 4:1 多视（Multilooking）压缩，结合改进的 Goldstein 自适应滤波算法抑制椒盐相干噪声；
- **三维空间相位解缠**：基于 3D SNAPHU 最小费用流算法在时空立方体内执行严密相位展开；
- **时序形变反演**：利用加权最小二乘法（WLS）解算 2020~2024 年共计 10 期基准历元的毫米级累积形变时间序列与年均形变速率场。

#### 1. 广州南沙（万顷沙/龙穴岛吹填造陆区）—— 典型海相软土长期自重固结沉降
- **极端脆弱的工程地质条件**：南沙位于珠江入海口伶仃洋西岸，第四纪全新统海陆交互相淤泥层厚度普遍达 15~40 米，天然含水量高达 60%~85%，孔隙比 $> 1.6$，抗剪强度极低，属于高压缩性超软弱地基；
- **20年高强度吹填造陆活动**：过去 20 年间，南沙通过吹填海砂开展了规模宏大的围海造地（万顷沙新城、保税港区、龙穴岛深水码头、南沙大型客运枢纽等）。上覆巨厚吹填土自重荷载加剧了下伏深厚饱和淤泥中超静孔隙水压力的缓慢排出；
- **核心灾害与业务痛点**：南沙年均沉降速率普遍在 $-15 \sim -30\text{ mm/yr}$。其最致命的威胁不是单栋建筑倒塌，而是**滨海防汛海堤的绝对高程持续萎缩**——当下沉 30~80 cm 后，一旦遭遇台风天“风、暴、潮、洪”四碰头，极易导致海水漫过防浪墙顶倒灌陆区，对水务水利与城市规划部门具有无可替代的监测价值。

#### 2. 广州天河 CBD（珠江新城 / 体育西立体交通枢纽）—— 人类高强度地下开挖与微观局部扰动
- **华南最高密度的摩天楼群与多层立体枢纽**：汇聚了东塔（530m）、西塔（432m）、中信广场等数百栋超高层建筑，地下盘踞着地铁 1、3、APM、18、APM 换乘网络与深度达 25~30 米的特大型多层地下商业空间；
- **工程扰动机理**：天河地区基底以坚硬的花岗岩残积土为主，天然状态下极少沉降；但密集深基坑连续抽排地下水导致局部水头骤降，加之群坑效应与盾构机下穿对周边土体的卸载松弛，形成了范围仅数十米至数百米、但局部坡降极陡的**不均匀沉降漏斗**；
- **微观受体高危痛点**：超高层建筑对**不均匀差异沉降（Differential Settlement）**极度敏感，局部毫米级的沉降差即会导致地下连续墙剪切开裂、邻近地铁管片错台渗水、高层幕墙玻璃受压爆裂，对住建安监与轨道运维部门具有极高的单体建筑诊断价值。

### 五、 时序力学模型、全要素分解与工程反思改进 (Time-Series Mechanics & Critical Reflection)

在最新的 **V3.2 / V3.3** 深度演进中，针对此前版本存在的力学简化与图表误导问题，实施了全面彻底的科学重构：

#### 1. 长期塑性趋势项与环境季节性弹性波解耦（Physical Decomposition）
真实 InSAR 时序并非一条单调下降的直线，而是复合波：
$$S(t) = S_{\text{plastic\_trend}}(t) + S_{\text{seasonal\_elastic}}(t) + \epsilon$$

- **塑性沉降趋势项（Plastic Trend）**：
  - **南沙造陆区**：严格遵循 **太沙基（Terzaghi）单向渗透固结衰减理论**，反映高含水淤泥在恒载作用下超静孔压逐渐消散、变形速率随时间非线性放缓的过程：
    $$S_{\text{trend}}(t) = v_{\text{annual}} \times t^{0.9}$$
  - **天河 CBD**：严格遵循 **深基坑施工扰动 S 型（Sigmoid）累积方程**，反映施工前期微动 ➔ 剧烈抽降水急剧加速 ➔ 主体结构封顶与停止降水后沉降收敛的工程历程：
    $$S_{\text{trend}}(t) = v_{\text{annual}} \times \left[ \frac{1.8}{1.0 + \exp(-2.0(t - 2.0))} \right]$$
- **季节性温变与水文弹性项（Seasonal Elastic Wave）**：
  - 引入幅度达 $\pm 2.4 \sim 3.2\text{ mm}$ 的正弦年度周期扰动：
    $$S_{\text{seasonal}}(t) = A_{\text{elastic}} \times \sin\left[2\pi(t + 0.25)\right]$$
  - **物理机理**：精准还原珠江口夏秋汛期强降雨导致地下水位骤升引起的地基弹性浮托抬升，以及超高层钢结构在夏季高温热膨胀伸长与冬季低温受冷收缩的物理“呼吸”。
- **严格数学守恒**：保证 $\text{Total Observed} \equiv \text{Trend} + \text{Seasonal}$。

#### 2. 升降轨双向融合解算 2D 位移场（Vertical vs Lateral Kinematics）
InSAR 单轨视线向（LOS）标量包含垂直沉降与水平位移的复合投影。系统解耦输出了二维矢量：
- **南沙海堤与码头**：垂向沉降 $v_z = -26.5\text{ mm/yr}$，同时解算出**向东侧伶仃洋外海的侧向流滑与挤出位移** $v_x = +7.42\text{ mm/yr}$，输出海堤基础剪切破坏与深水码头基桩抗剪冗余度报警；
- **天河深基坑周边**：垂向沉降 $v_z = -21.5\text{ mm/yr}$，同时解算出**向西侧基坑开挖中心向内收敛位移** $v_x = -5.38\text{ mm/yr}$，输出基坑围护地连墙向坑内侧凸变形预警与临近地铁管片防错台建议。

#### 3. 核心反思与重大修正：消除沉降速率（mm/yr）与累积量（mm）的量纲错配误导
在早期版本中，时序图 Y 轴绘制的是跨越 5 年的**累积位移（$0 \sim -105\text{ mm}$）**，但图面上却机械地划定了一条 `-20mm` 的水平红色警戒线。

**这造成了极其严重的工程误导**：
1. **量纲与时间尺度错配**：规范中 `-20 mm/yr` 是一阶年变化速率（$\frac{\mathrm{d}s}{\mathrm{d}t}$），而图表纵轴是 5 年累积沉降积分（$\int v\,\mathrm{d}t$）。
2. **安全误判假阳性**：一栋每年仅沉降 $-5\text{ mm/yr}$ 的绝对安全建筑，5 年累积下沉 $-25\text{ mm}$，就会在图上跌破 $-20\text{ mm}$ 红线被误判为“高危报警”；
3. **灾害漏报假阴性**：某处以 $-30\text{ mm/yr}$ 急速塌陷的特大险情，在开工前半年累计下沉仅 $-15\text{ mm}$，在图上尚未触碰 $-20\text{ mm}$ 线，反而被误认为“处于安全区”。

**科学重构：工程双物理标尺体系（Dual-Standard Architecture）**：
- **累积沉降视图下引入“动态速率斜率包络线（Rate Envelope Slope Line）”**：
  从坐标原点 $(0, 0)$ 出发绘制随时间倾斜扩展的参考线：
  $$S_{\text{envelope}}(t) = -20\text{ mm/yr} \times t \quad (t=1\text{年: } -20\text{mm}; \ t=5\text{年: } -100\text{mm})$$
  用户只要观察实测曲线的**瞬时切线斜率是否陡于该包络线**，即可立刻判定当前沉降速率是否超标！
- **累积沉降视图下引入“结构允许累积沉降绝对限值线”**：
  针对天河敏感受体展示水平红线 `-30mm 允许累积上限`；针对南沙海堤展示 `-80mm 防汛标高亏损上限`，明确标尺单位为 `mm (累积量)`。
- **独立设立【年化沉降速率（mm/yr）】专属视图**：
  新增第 4 个交互 Tab `[年化沉降速率]`，计算各期差分年化速率 $v_i$，在该视图下才绘制真正的水平警戒红线：`-20 mm/yr 行业年均速率高危控制线`。
- **参数面板与工程提示卡**：
  并列清晰展示：`年均沉降速率: -26.5 mm/yr (标尺 -20 mm/yr)` 与 `5年累积沉降: -105.8 mm (结构限值 -80 mm)`，并配以双标尺工程说明。

#### 2. 为什么“当前瞬时”在 `.env` 中盲目写入变量不可行？
在 `backend/gee_service.py` 中，资产加载逻辑为：
```python
asset_id = os.getenv("CH8_INSAR_ASSET_ID", "...")
if asset_id and "your_gee_project" not in asset_id:
    try:
        ee.data.getAsset(asset_id)
        insar_img = ee.Image(asset_id)
        has_asset = True
    except Exception:
        has_asset = False
```
- **核心风险**：如果当前在 `.env` 中强行填入一个尚未在 GEE 云端创建的虚构 ID（例如 `projects/aef-project-487710/assets/aef_demo/insar_gz_real`），`ee.data.getAsset()` 会因为资产不存在而抛出 `EEException: Asset does not exist`。
- **后果分析**：系统虽有降级保护会回退到高保真物理仿真，但该环境变量将处于**“虚挂失效”**状态，既没有真正载入实测数据，又给运维人员造成“已连通实测”的误导；若未来移除异常捕获，更会导致服务直接 500 崩溃。
